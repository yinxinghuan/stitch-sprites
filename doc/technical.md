# 《拆线精灵》技术文档

## 1. 技术栈

- **语言与构建**：TypeScript 5.9、Vite 6，`base: './'` 相对路径构建。
- **界面**：原生 DOM 与 CSS；固定逻辑网格放在响应式竖屏界面中，不依赖整页缩放。
- **渲染**：HTML Canvas 2D 绘制绣布、十字针脚、底图和地面行走精灵；DOM 绘制 HUD、五轴位、线轴堆和结果弹层。
- **声音**：Web Audio 动态合成按压、出发、拆线、等待、危险、完成和失败声音；首次用户输入后才恢复 `AudioContext`。
- **平台**：入口加载远程 `guest-shell.js`；浏览器存储通过 `alteruLocalStorage` 按当前部署 UUID 隔离。
- **外部依赖**：运行时代码无第三方包，构建期仅依赖 TypeScript 与 Vite。

## 3. 核心模块

### 状态与拆线路径

`GameEngine` 保存当前关卡、二维格子、四列线轴堆、五个活动轴位和阶段。每轮工作通过 `findReachable()` 从棋盘外侧对空白格做 BFS；与外部可通行区域四向接触的未拆针脚才是当前可达目标。每个活动线轴按容量每轮派出 4–12 个精灵，多个颜色和多个目标可以并行工作。

`createWalkPathfinder()` 在加了一圈外部通道的棋盘上执行一次共享 BFS，从底部中央洞口出发，只允许经过棋盘外沿、空白格和已经拆除的格子；同一工作批次的 4–12 个精灵复用这棵最短路径树，再分别回溯到目标针脚旁。每项任务保存完整路径、430–920ms 单程时长与 `departMs`。`departMs` 按工人索引以 52ms 为基础间隔递增，并叠加 0–15ms 确定性微差，保证洞口严格排队而非同帧生成。渲染器在路径前 20% 逐步放开横向编队，返程进入洞口前则重新收拢。

关卡文件保留 10×10 与 14×14 的决策母版，`createCells()` 在运行时按 3×3 展开为 30×30 教学关和 42×42 正常关，`createColumns()` 同步把容量乘以 9。`_qa/solve-levels.ts` 直接对展开后的真实状态穷举列选择，验证每关存在完整解，并验证正常关存在五轴位堵死路径；浏览器脚本随后用正常点击和真实节拍复现这些路径。

棋盘进行态使用占自身格约 98.5% 的完整针脚颗粒。当前 3× 密度关卡保留深色方形底板与两道交叉线，省略缩小后难以辨认的中心辅助符号；Canvas 使用浮点单格尺寸填满可用画幅，避免高密度网格因整数取整整体缩小。可达状态使用很窄的静态浅色轮廓，完成态底图不受密度调整影响。

精灵抵达后先进入 260ms 接触阶段；约 130ms 时针脚才被标记为 `cleared` 并重新计算可达区域。渲染器在目标格中心重画两股交叉线，将其朝精灵方向拔起、抖松、卷成带螺旋纹的线团，同时绘制短纤维和空位释放环。返程显示圆形携带线团，最后用 220ms 在洞口下沉、缩小、淡出并留下同色回收轨迹。精灵身体、触角端点、胸前几何符号和携带物都从同一 `ThreadColor` 读取；胸前符号提供非颜色识别。线轴容量耗尽后离开轴位；五个轴位全部占用且没有任何可执行目标时进入失败。所有针脚清空后进入完成，并仅在此时绘制隐藏底图。

### 渲染性能

绣绷、布面与全部针脚绘制到离屏静态缓存，只在尺寸、可达状态或针脚状态变化时重建；没有活动精灵时不运行 `requestAnimationFrame`。30×30 与 42×42 针脚都按颜色合并成 `Path2D` 批次，不再逐颗计算圆角、阴影和多次描线。每帧动态层只绘制当前活动精灵、携带线团和洞口回收演出，避免单位行走时重复重画 792–1656 个静态针脚。

### 屏幕适配与渲染

界面以 `100dvh` 为竖屏容器，绣绷尺寸由视口宽度、高度和 430px 上限共同约束。Canvas 根据 CSS 尺寸和最多 2× 的设备像素比重建实际缓冲区。320×568 使用短屏规则压缩纵向间距，但不缩小 44px 功能按钮。

### 输入与恢复

- 线轴使用 `pointerdown`，数字键 1–4 可选择对应列。
- 首次 `pointerdown` 不创建音频上下文；全局首个 `pointerup` 在用户手势内解锁声音，使线轴状态先进入画面。正常 CPU 测试的事件派发约 1.6ms、首个可见槽位约 4.2ms。
- 重开和声音按钮使用普通 `click`；`R` 重开当前关。
- 教学关第一次只允许选择第一列；完成一次真实拆线后按当前外层颜色解锁可用线轴。
- 失败重开保持关卡与线轴顺序不变。

### 音频、多语言与存储

音频失败不影响玩法。`AudioContext` 在首次 `pointerup` 或声音按钮点击时恢复，不参与 `pointerdown` 的权威状态更新。高密度网格每拆 3 个细针脚才触发一次拨弦音，避免并行小队形成蜂鸣。所有用户可见文案通过 `t()` 从 zh/en 字典读取。当前持久状态只有 `stitch_sprites_level`，通过 `alteruLocalStorage` 保存最高已开放关卡；语言覆盖使用同一适配器下的 `game_locale`。

游戏没有自有玩法后台、排行榜、头像、好友信息或微信权限依赖。`worker/index.js` 只为正式静态托管提供 `/api/health`，不保存或修改游戏状态。

## 4. 扩展点

- **新增关卡/调整线轴顺序**：编辑 `src/game/levels.ts`；每种颜色的线轴容量必须精确等于棋盘针脚数量，启动时会机械校验。
- **调整可达和失败规则**：编辑 `src/game/reachability.ts` 与 `src/game/engine.ts`。
- **修改线色与无障碍符号**：编辑 `src/game/palette.ts`，并同步检查 Canvas 与 DOM 表现。
- **更换底图或精灵绘制**：编辑 `src/game/renderer.ts`；底图必须继续只在完成状态展示。
- **调节手感与声音**：工作节拍位于 `src/game/engine.ts`，绘制时长位于 `renderer.ts`，声音参数位于 `audio.ts`。
- **调整布局与材质**：编辑 `src/styles.css`，并复验 390×844 与 320×568。
- **修改文案/语言**：编辑 `src/i18n.ts`；不得在视图或引擎中硬编码用户可见文字。
- **增加平台分享或后端**：在独立模块中接入，并更新本文件；核心玩法不得依赖头像或好友权限才能运行。
